# Skill: DID 稳健性检验自动化 (DID Robustness Checker)

## 1. 触发条件
当用户要求“对 DID 模型进行稳健性检验”、“跑安慰剂检验/平行趋势”或“验证因果识别假设”时，触发本 Skill。

## 2. 背景知识
- 掌握因果推断中双重差分（DID）的标准识别假设（平行趋势、SUTVA等）。
- 熟练使用高维固定效应包（如 Python 的 `linearmodels.PanelOLS`，或 Stata 的 `reghdfe`）。
- 理解“估计量（Estimand）”与“估计值（Estimate）”的区别。

## 3. 工作步骤
1. **环境侦察**：首先读取项目的 `README.md` 或数据描述文件，自动识别并提取核心变量：结果变量 $y$、处理变量 $D$、个体维度 $id$、时间维度 $t$，以及建议的聚类层级（切勿硬编码变量名）。
2. **基准对齐**：使用识别出的变量重跑基准双向固定效应回归，比对核心系数与已有主结果（如 `output/stata_did_results.csv`）是否一致。若不一致，立刻停止并向用户报告数据差异。
3. **按需检验**：根据用户的具体要求（如 R1平行趋势、R2安慰剂等），代入变量执行对应的统计代码。
4. **归档落盘**：将每一次检验的“目的、Prompt、结果摘要、观察结论”按四要素模板格式化，强制自动保存至 `prompts/robustness/*.md` 目录下，并在 `output/robustness_summary.md` 中追加记录。

## 4. 检查清单 (Checklist)
- [ ] 是否在执行前确认了基准系数一致？
- [ ] 做安慰剂检验（R2）时，是否显式设置了随机数种子（Random Seed）以保证可重复性？
- [ ] 样本调整或增加高维固定效应后，是否核对了自由度和观测值（$N$）的合理下降？
- [ ] 生成的图表（如平行趋势图）置信区间是否正确标注？

## 5. 边界条件
- 绝对禁止修改 `data/raw/` 目录下的任何原始数据，所有操作必须在内存或临时数据框中完成。
- 当数据被标记为“合成数据演示”时，禁止在解释中过度引申到真实的政策/经济因果影响。
- 绝不虚构任何文献来支持实证发现。

## 6. 验证方式
- 检查 `output/` 目录下是否成功生成对应的 `.csv` 和 `.png` 文件。
- 检查回归结果表格中是否包含系数、聚类标准误、t值、p值及准确的 $N$。
- 代码执行后不报错，且输出的 Markdown 文件严格包含“四要素”结构。

---

## 7. 一般适用性（如何迁移）

**换一个研究主题（如“最低工资对就业”）：**
- **我的 Skill 需要改哪些地方？** 几乎不需要改动核心逻辑。可能仅需根据新项目的数据特征，微调“检查清单”中关于特定异常值处理的标准。
- **不需要改哪些地方？** 前六个模块（触发、读取数据自动识别变量、基准对齐、执行检验、边界防越界、强制归档落盘）完全不需要改动。
- **这说明了什么？** 这说明该 Skill 已经从“本项目的定制脚本”进化为“可迁移的制度”。它不是一套写死了 `digital` 和 `log_tfp` 的死代码，而是一个懂得“先看说明书、再对齐基线、最后按流程办事”的通用因果检验流水线。
