# 迭代反思（≥2 轮）

## 第一轮：Skill 的通用化迭代
- **我观察到的关键问题（不够通用）**：
  在初始版本中，我发现 AI 在跑聚类标准误时，直接把代码写死了 `cov_type='cluster', cluster_entity='firm_id'`。虽然在跑当前数据集时没报错，但这极不具备通用性。如果换一个省级面板数据，聚类层级应该变成 `province`，这个 Skill 就会崩溃报错。
- **我做的修订**：
  我修改了 `.claude/skills/robustness-check/SKILL.md` 的“工作步骤”，加入了前置的【环境侦察】。强制要求 AI：“首先读取 README.md 或代码注释，自动识别并提取核心变量...以及建议的聚类层级（切勿硬编码）”。
- **证据（对比）**：
  - **修订前输出片段**：`执行回归：smf.ols('log_tfp ~ digital + EntityEffects + TimeEffects', data).fit(cov_type='clustered', clusters=data['firm_id'])`
  - **修订后输出片段**：`读取README得知聚类要求为企业级。执行回归并动态传入聚类参数：fit(cov_type='clustered', clusters=data[cluster_var])`

## 第二轮：综合评估 Agent 的防呆与深度迭代
- **我观察到的关键问题（无脑复读机、缺乏反思）**：
  第一版 Agent 生成的报告只是把 Part A 里的 11 项检验结果冷冰冰地罗列了一遍，最后加上一句“因此结论非常稳健”。它完全没有结合“数字化转型”的经济学直觉，也没有指出双重差分法（DID）固有的识别缺陷。
- **我做的修订**：
  我在 `.claude/agents/eval-did-robustness.md` 中增加了强制性的流程步骤 `S4 残余威胁` 和 `S5 主题解读`。明确规定：必须结合处理机制指出未排除的威胁（如不可观测的动态行业冲击），必须将统计结论翻译为论文的 Discussion 写作建议。
- **证据（对比）**：
  - **修订前输出片段**：`3. 结论稳定性：R1到R7均通过了检验，核心系数显著。该 DID 模型非常完美，没有明显威胁。`
  - **修订后输出片段**：`4. 残余威胁：虽然控制了行业趋势，但如果2020年恰好发生了未被观测到的、与企业数字化高度相关的组织结构剧变（且不随时间稳定），FE将无法吸收这种冲击。论文写作时需克制，必须如实报告平行趋势仅仅是诊断，并非因果关系的终极证明。`

## 一般适用性论证
- **换一个研究主题，我的 Skill/Agent 需要改哪里？不需要改哪里？**
  如果换成“最低工资对就业”的主题，我的 Skill 核心框架完全不需要改，它能自动抓取新的识别目标并跑通流程。综合评估 Agent 只需要在 S5（主题解读）的提示词中，将背景知识从“数字化/TFP”替换为“劳动力市场/摩擦成本”即可。
- **这说明了什么？**
  这证明我设计的不再是“本项目的定制跑数脚本”，而是真正意义上的“可迁移的因果推断审查制度”。
